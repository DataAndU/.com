# Billing API contract

Router mounted at `/api`. Verified Clerk authentication via shared `current_user` dependency (same-origin session cookie or supported bearer session) required except signed Razorpay webhook. Admin endpoints require `User.is_admin`. Amounts are integer INR paise; dates ISO-8601 UTC. Errors use `{detail:string}`. Billing defaults to test mode; live billing is an explicit operational opt-in.

- `GET /billing/plans` → `{plans: Plan[], testMode:boolean, checkoutAvailable:boolean}` (active plans for the user's role).
- Plan: `{id,name,role:"buyer"|"provider",cycle:"monthly"|"yearly",amountPaise,currency:"INR",active}`. Free access is implicit, never a charged subscription.
- `GET /billing/status` → `{paid:boolean,freeContactLimit:number,subscription: Subscription|null,testMode:boolean}`.
- Subscription: `{id,planId,planName,amountPaise,currency,cycle,status,currentPeriodEnd:string|null,cancelAtPeriodEnd:boolean,razorpaySubscriptionId:string|null,scheduledChange:{planId,planName,amountPaise,effectiveAt}|null}`.
- `POST /billing/subscribe` body `{planId:string,discountCode?:string}` → `{subscription:Subscription,checkout:{keyId,subscriptionId,name:"Pontreol",description},testMode:boolean}`. Opens Razorpay subscription Checkout in the configured mode. Live checkout requires all live credentials including the webhook secret. Missing, wrong-prefix, or incomplete configuration returns 503; checkout creation never grants access.
- `POST /billing/verify` body `{subscriptionId:string,razorpayPaymentId:string,razorpaySignature:string}` → `{subscription:Subscription}`. Backend verifies signature and fetches authoritative subscription/payment/invoice before granting access.
- `POST /billing/cancel` body `{subscriptionId:string}` → `{subscription:Subscription}`. Cancels at period end; no immediate refund. Free downgrade means cancel then use free after paid-through date. Creating a second subscription is blocked (409) while an existing subscription is pending or has unexpired paid access; use change-plan for supported upgrades/downgrades.
- `POST /billing/change-plan` body `{subscriptionId:string,planId:string}` → `{subscription:Subscription}` schedules a same-role, same-cycle paid upgrade/downgrade for the next renewal using Razorpay's subscription update API. No immediate proration. Only active, non-cancelling subscriptions; one pending change. Cycle changes require cancel/re-subscribe. Existing discounts do not transfer to the new plan; the new plan's full admin-configured price is returned. An ambiguous provider timeout keeps the pending intent to prevent competing changes and requires provider/admin reconciliation; never retry automatically.
- `GET /billing/payments` → `{payments:[{id,subscriptionId,amountPaise,currency,status,createdAt}]}`.
- `POST /billing/webhook`: raw signed Razorpay body; headers `X-Razorpay-Signature`, `X-Razorpay-Event-Id`; returns `{received:true}`. Events and payment IDs deduplicated durably.
- `GET /admin/billing/plans` → `{plans:Plan[]}`; `POST /admin/billing/plans` and `PUT /admin/billing/plans/{id}` accept `{name,role,cycle,amountPaise,active:true}` → Plan. Existing subscriptions retain snapshots.
- `GET /admin/billing/discounts` → `{discounts:Discount[]}`; `POST /admin/billing/discounts` and `PUT /admin/billing/discounts/{id}` accept `{code,kind:"percentage"|"flat",value:number,planIds:string[],startsAt:string,endsAt:string,maxUses:number,active:boolean}` → Discount (same fields plus `id,uses`). Percentage value 1–100; flat value integer paise. All dates require timezone. Discounts apply to **every recurring installment** by creating a dedicated provider plan at discounted price; minimum discounted amount 100 paise. Usage reserved atomically on subscription creation; abandoned checkouts consume one use, deliberately preventing oversubscription. No introductory-only discounts.
- `GET /admin/billing/settings` and `PUT /admin/billing/settings` body → `{freeContactLimit:number}`.
- `GET /admin/billing/revenue` → `{currency:"INR",testMode:boolean,totalCapturedPaise:number,payments:Payment[],subscriptions:Subscription[]}`. Returns actual captured records for the configured mode only, not projections. Test money is never included in live revenue.

No prices seeded. Admin must configure paid plans. Default free contact limit is 5 until changed by admin. `RAZORPAY_MODE` accepts only `test` or `live` and defaults to `test`. Test mode reads only `RAZORPAY_TEST_KEY_ID` (`rzp_test_…`), `RAZORPAY_TEST_KEY_SECRET`, and `RAZORPAY_TEST_WEBHOOK_SECRET`. Live mode reads only `RAZORPAY_LIVE_KEY_ID` (`rzp_live_…`), `RAZORPAY_LIVE_KEY_SECRET`, and `RAZORPAY_LIVE_WEBHOOK_SECRET`. Key prefixes are validated and configurations fail closed. Merely supplying live keys does not activate live mode; operations must separately set `RAZORPAY_MODE=live` after operational approval.

Subscriptions carry an immutable mode tag in their stored plan snapshot without a schema migration; legacy untagged subscriptions are test records. Status, access, cancellation, plan changes, payment history, webhook receipts, and admin revenue are restricted to the active mode. Live payment and webhook receipt identifiers are namespaced locally. Cross-mode reconciliation and cross-mode webhook-note recovery are rejected.

Configure the matching-mode Razorpay subscription lifecycle webhook, especially `subscription.charged`, `subscription.pending`, `subscription.halted`, `subscription.cancelled`, and `subscription.completed`. Payment-only events do not grant access. Auth-only checkout charges do not grant paid access; a captured recurring invoice with `billing_end` is required. Unknown subscription creation outcomes are deliberately held for webhook/provider reconciliation rather than risking duplicate subscriptions. Buyer-provider marketplace transactions remain offline; Razorpay charges only Pontreol platform subscriptions.
